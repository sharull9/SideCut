## Reference and implementation

The baseline remains Tandem `735a9b8e162c1f951044baa892d94993869f2e77`.
The local reference checkout was inspected for `AudioLevels.swift`, normalization
in `Editing.swift`, `AudioEnvelope.swift`, `AudioEffects.swift`,
`AudioDynamics.swift`, `Limiter.swift`, `PitchShift.swift`, `LoudnessMeter.swift`,
and master gain selection in `Export.swift`. The checked audio/core files have
no diff against the pinned revision. Ported modules retain the notice pointing
to `tests/fixtures/tandem/TANDEM-LICENSE`. No dependency was added.

- Phase 073 adds gain, gain animation, equal-power fades, and 3 ms edge
  micro-fades. Gain keys replace base gain. Normalization is a separate constant
  multiplier. Gain/fade breakpoints use the reference eight fade subdivisions
  and at most 24 subdivisions between gain keys. Through cuts without a source
  or level discontinuity omit micro-fades; disabled/muted neighbors do not
  suppress them. The Audio inspector edits gain, fades, mute, and levelling.
- Phase 074 ports the two K-weighting biquads, 400 ms absolute/relative gates,
  three-second loudness range windows, and four-phase, 12-tap true peak meter.
  Source analysis uses its original channel count, including reference 5.1
  channel weights. Cache keys combine SHA-256 of the entire source file with an
  analysis version. Measurements persist separately in IndexedDB, with a bounded
  memory cache. Cache write failures do not prevent analysis. Cancelled/failed
  decoding is closed and does not publish a partial measurement.
- Phase 075 adds `normalizeSpeech` to contracts and the existing coordinator.
  Camera/other media and audio clips on cut tracks qualify. Locked tracks are
  skipped with warnings. Muted speech is levelled for later unmuting. Base gain
  resets to zero, target follows project speech loudness, gain animation stays,
  and source adjustment is limited to ±30 dB. Silent measurements add no lift.
  The UI measures local sources before submitting one revision-checked batch.
- Phase 076 adds duration-preserving portable pitch/speed conversion. The first
  enabled non-neutral pitch effect is used, including semitone keyframes. The
  normal inspector range remains ±12 semitones; imported/keyframed rendering
  clamps to ±24 as in the reference. Speed changes retain the original pitch.
  The portable implementation uses overlapping Hann grains, not Apple TimePitch.
- Phase 077 ports the compressor's loudest-channel 10 ms RMS detector, soft knee,
  shared stereo reduction, attack/release smoothing, and makeup gain. Normalizing
  measured speech above the ceiling inserts a 3:1 compressor at speech level
  plus 6 dB, unless any compressor already exists.
- Phase 078 ports the four-times oversampled true peak limiter, 5 ms lookahead,
  held/averaged reduction, and release. Lookahead is compensated and the tail
  flushed without moving sample positions. Normalization adds protection only
  to audible speech whose measured levelled peak exceeds the ceiling. Any
  existing limiter, including a disabled limiter, prevents automatic insertion.
  Export measures the whole mix, applies bounded master gain, checks candidate
  gains through the limiter, interpolates/extrapolates toward the loudness target,
  and applies the project peak ceiling. Preview plays before the export master,
  matching the reference's distinction between speech balance and export level.

Dynamics process the normalized base level, before gain animation and fades.
Clip preview and export consume the same prepared PCM and mixer. Expensive
processors for later clips finish before the preview clock starts. Seeking
retains DSP state from the clip start, and pause/seek/close abort actual work.
Long DSP loops yield for cancellation. Source audio is never uploaded.

Changed implementation is in `packages/core/src/audio-{plan,processing,editing}.ts`,
`loudness.ts`, browser `audio.ts`/`audio-analysis.ts`/`export.ts`, command routing,
and the workspace Audio inspector, settings, effects, export, and preview.

## Remaining limits

Only Windows Chromium was verified. Firefox/WebKit, other operating systems,
native Tandem reopening and audio comparison, real touch devices, and a complete
accessibility audit remain unverified. Phase 028 public-host acceptance is still
pending. No deployment was made.

Pitch conversion is approximate and may smear transients or introduce modulation
on speech/music, especially at extreme ratios. Tone frequency/duration checks do
not establish perceptual equivalence to Apple TimePitch. Gain micro-fades are
sampled directly at their edges; combining them with the sampled main envelope
can differ slightly from the reference's union of breakpoints. Dynamics with
speed changes run in timeline time in this browser implementation.

Processed clips use full stereo float buffers, not a worker/GPU pipeline. Each
processed clip is limited to five timeline minutes and ten source minutes.
Preview preparation permits at most ten minutes of combined processed clip
duration, including overlaps. Large projects can consume hundreds of MiB and
take time before playback starts. Source hashing supports files up to 512 MiB
and temporarily reads the whole file into memory. Metering and processing yield
but still use the browser thread. No large-project performance claim is made.

Audio mixing uses the first two channels for sources with more than two channels;
surround analysis follows reference weights but no surround downmix was added.
Codec true peaks can vary from the raw limiter, so native export checks allow
0.5 dB codec tolerance. The measured hot fixture remained below its ceiling.
Interactive undo still resets on reload. Existing media portability, codec,
five-minute, 1080p, and 1-60 fps export limits remain.

Voice cleanup/isolation, pan, audio crossfades, generated transition sounds, and
live mix meters remain pending. Unsupported audio effects and nonzero isolation
or pan fail preflight. The next phase is 079, voice cleanup.
