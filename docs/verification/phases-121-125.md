## Edits and history

`apply` supports expected revisions, author/label, idempotency keys and dry runs.
It reports created IDs, changed/added/removed clip IDs and resulting duration.
Dry runs use a detached coordinator and do not commit. Actual edits use the
same coordinator as renderer IPC. `X-Tandem-Author` supplies the author when a
request does not specify one. Concurrent stale edits fail with HTTP 409 before
committing any commands.

`undo` and `redo` support expected revisions and counts of 1-500, returning each
completed step's label/author. Empty stacks return `nothingToUndo` or
`nothingToRedo`, with HTTP 409. Coordinator stacks now reconstruct from the
saved journal when a project reopens. `history` returns the current undo/redo
state and durable journal edits, newest first, with a 1-1000 result limit. New
journal entries retain timestamps; older entries without dates stay undated.

`diff` accepts a journal revision, a relative project snapshot, or an export
whose adjacent `.tandem` snapshot is available. Baseline projects must have the
same project ID and remain within the managed project folder. `restore` previews
selected clip IDs or a time/track selection, then applies as one undo step when
`apply: true`. Property-only restoration patches clips in place and preserves
existing transitions. Other supported restorations remove/reinsert selected
clips and add missing media references, with coordinator validation before any
commit. A stale project rejects the whole edit.

Remaining compatibility: diff details use field-change descriptions rather than
the complete upstream prose/shift classifications and per-edit diff records.
History activity events and edit-place summaries are not populated. Reviewed
baselines return HTTP 501 until phase 126. Restoring timing/placement of clips
with transition dependencies returns 501; missing original tracks are refused.
No partial transition restoration is attempted. The API accepts SideCut's
existing command variants; upstream command-alias decoding is not added here.

## Speech and helpers

`transcript`, `search`, `pauses` and `tighten` read the renderer's actual cached
transcripts, including the existing waveform alignment. Transcript scope can be
media, clip or timeline. Missing analyses stay explicit. Search retains partial
cut matches and unused-source matches. Pause minimum defaults to 0.6 seconds;
tighten uses the existing UI planner, including protection, widening and locked
track handling. Tighten remains a preview until `apply: true`.

`transcribe` resolves media IDs, clip IDs and paths/basenames, marks supported
audio media through a shared edit and schedules the existing local worker.
`wait: true` waits for its result; otherwise work remains in the editor's job
queue. A request can wait up to ten minutes. Cancellation interrupts an owned
transcription job; existing shared analysis jobs are not cancelled by another
waiter's departure. Closing/replacing the session cancels its work. Runtime
verification used a recorded synthetic transcript cache and did not download or
run the speech model. First-run model acquisition and the complete upstream
wait/timeout result contract remain unverified. A transport timeout currently
returns unavailable rather than a complete upstream `WaitResult`.

`join`, `captions`, `short` and `cards` return proposed commands and apply through
the same host coordinator when requested. Captions and tighten obtain plans
from the renderer; pure join/short/card plans use shared core functions directly.
Short copies can be written as independent `.tandem` projects in `exports`, with
portrait adopted, while leaving the original project unchanged. Previews never
write a copy. Helper plans preserve author labels and reject stale application.

Join's detailed grouped/skipped explanations are not a complete wire-format
port. Automatic section-card whooshes are not installed by this adapter; the
result warns and reports no sounds. Card insertion uses marker times and warns
that speech-aware section cut selection is unavailable. Explicit `sounds: false`
is the verified card path. Font auto-install result metadata is not implemented.

## Inspection and rendering

The host routes named operations to one ready, trusted renderer over correlated
IPC requests. Responses must come from that same main frame and match the
request's project generation/revision. Closing a window, HTTP cancellation or a
deadline rejects the request; renderer jobs receive cancellation. The bridge
does not expose tokens, arbitrary file I/O or executable arguments. Actual
mutations remain host commands rather than a second renderer authority.

`frame` returns a composited PNG, with aspect-preserving maximum dimensions.
`frames` returns a labelled contact sheet of explicit times and/or interval
samples. An explicit interval end is included; an implicit timeline end is not.
Times are computed at flick precision, deduplicated and sorted. Sheets allow
1-48 frames, tile widths 64-1920 and at most 32 million total pixels. Frame sizes
are bounded to 8192 per side. Requests outside the timeline are rejected.
Missing fonts and mattes produce warnings; absent mattes render with their
background visible. `screenshot` uses Electron's actual editor-window capture,
not a rendered timeline frame. PNGs are returned as base64 or written to a
permitted output filename.

`clip` and `export` render requested ranges through the shared compositor.
Review output has a 720-pixel short side, with an upscaling warning when needed;
`youtube1080` uses 1080, and `short` uses the project's portrait format. `final`
preserves the current format within browser size limits; `webm` selects WebM.
Video supports native H.264/AAC MP4 or VP8/Opus WebM. Audio-only clips mix directly
to stereo 48 kHz, 16-bit PCM WAV, then optionally encode to AAC M4A or Opus WebM.
The direct PCM path avoids Opus priming loss in WAV stems. Selecting audio tracks
by ID, name or lane label disables mastering for stems. Other mixes use the
existing loudness target/limiter. Each render writes an adjacent project
snapshot for later diff/restore.

Outputs are exclusive new files inside the managed project's `exports` folder.
Absolute/traversing paths, nested output directories, symlink escapes, reserved
Windows device names and incompatible extensions are refused. Existing output
is never overwritten. Failure to save an export's sidecar removes the newly
created export. Native jobs keep fixed, shell-free arguments and existing
cancellation, timeout and 256 MiB limits.

`loudness` measures source files or a selected rendered mix range through the
same audio processing code, including source normalization. It returns target,
speech level, source measurements, clip levels, centered 400 ms/3 s curve
windows and merged over-threshold peak stretches. Silent values become JSON
null. Ranges are limited to five minutes and 1,000 measurement steps. Per-track
gain-lane verification returns HTTP 501. Exact macOS mix-meter numerical parity
has not been established.

Remaining rendering limits: the browser compositor still caps output at
1920x1080 or 1080x1920, 1-60 fps and five-minute timelines. H.264 uses a VP8/Opus
intermediate and native CRF encoding, not Tandem's bitrate/colour/hardware
encoder configuration. `youtube4k` explicitly returns 501. Complete preset
aliases, master-quality HEVC and codec/bitrate parity remain pending. The
backend's reported elapsed time excludes host transcoding. Full first-run font,
matte and model workflows are not certified by this batch's synthetic runtime.
