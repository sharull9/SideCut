## Implemented

- 025: `blade` preserves left IDs and creates deterministic right IDs. A batch
  follows descendants when subsequent commands name an original clip. Linked
  partners share a new right-hand link group. Source-in, keyframes, fades, text
  animation boundaries, and transition references follow the reference slicing
  rules. Split at playhead uses selected clips crossing the playhead, falling
  back to targeted tracks. Ctrl/Cmd+K and Ctrl/Cmd+B invoke that action.
- 026: non-ripple `trim`, source bounds, linked edge deltas, pointer trim handles,
  keyboard edge nudging, and numeric timeline start/end fields. Numeric edits
  enter one atomic batch. Invalid ranges, source overruns, overlaps, and locked
  partners reject without partial changes.
- 027: `moveClips` in place mode and non-ripple `removeClips`. Dragging snaps to
  frames and nearby clip edges/playhead. Escape and pointer cancellation discard
  a gesture before any command. Cross-track moves validate destination kind and
  locks. Lift/Delete leaves a gap; undo restores the selection's content.
- 028: local VP8/Opus WebM rendering through MediaBunny/WebCodecs. The shadcn
  export dialog shows capability errors, progress, cancellation, and a download
  action. It resolves used sources before encoding and closes readers afterward.
  Missing/unsupported sources cannot yield a partial download. Editing/file
  operations are disabled during rendering. Export cancellation or session close
  aborts encoding. Production-preview round-trip verification passes locally;
  **public hosted-URL acceptance is still pending**.
- 029: `link`/`unlink`, linked selection, synchronized moves, trims, cuts, and
  removal. Link merges existing groups; unlink clears selected membership and
  removes singleton groups. The inspector can trim a linked group using its
  first clip's edge delta.
- 030: `rippleDeleteRange` and ripple `removeClips`. Range removal cuts cut-mode
  tracks, maps follow-mode clip edges while retaining their source head, leaves
  off-mode tracks unchanged, skips locked tracks with visible notes, and maps
  markers for global ripple edits. Selected-clip ripple removal unions ranges
  and rejects misaligned remaining clips on touched tracks.

All changes go through the shared coordinator, revision checks, existing save
queue, and undo/redo. There are seventeen implemented command families, some
with the explicit mode restrictions above. Deterministic IDs use the reference
SplitMix64 algorithm with a seed derived from project/revision/idempotency key.
This supports deterministic batches from the same starting state; a persistent
journal and crash replay are not implemented yet.

## Limits and remaining acceptance

Phase 028 has no public deployment verification yet. The production build was
served on localhost; no public host, hosting account, or deployment was created.
Native Tandem reopening, Firefox/Safari, other operating systems, installed
desktop builds, mobile editing, accessibility scanning, and long-project export
performance remain unverified.

The first exporter supports basic source edits on at most one enabled picture
track and one enabled sound track, with solo/mute applied. It caps output to
1920×1080 or 1080×1920, supports 1–60 fps and sequences up to five minutes, uses
an in-memory output buffer, and rounds duration up to a complete frame. Black
gaps and contained image sizing match the current source-preview slice. It does
not yet provide full Tandem rendering, audio mixing, loudness processing,
transitions, compositing, keyframes, effects, speed/freeze/hold processing,
alternate formats, or a render queue. Unsupported processing rejects visibly.
The five-minute cap is a guard, not a memory/performance guarantee.

Ripple trim and overwrite moves remain explicit unsupported modes. Editing a
track with transition-bound sound rejects until sound ownership can be preserved
by the later transition phases. Basic transition references are repaired, but
transition rendering and full sound ownership parity are not claimed. Undo is
still memory-only. Automatic audiovisual placement, range cutting, insert time,
and the remaining editing operations are later roadmap work.
