# Phases 013-018 verification

Verified on Windows with Headless Chromium 156 on 2026-10-21. The reference remains
Tandem revision `735a9b8e162c1f951044baa892d94993869f2e77`.

## Implemented

- 013: the inspector edits project name, canvas width/height, and rational frame
  rate through one atomic command batch. Actual revision and undo/redo labels
  follow the authoritative coordinator. Read-only and busy sessions disable edits.
- 014: project snapshots are serialized into IndexedDB. The interface reports
  opening, saving, saved, read-only, and failed-save states. Retry saves the latest
  in-memory snapshot. A failed write preserves the previous committed save.
- 015: a browser file input opens validated `.tandem` JSON; Download project
  exports a validated snapshot. Unknown supported envelope/project fields remain
  intact. Invalid JSON, unsupported schemas, and conflicting saved copies are
  rejected before replacing the active project. Missing source files appear
  separately in the media bin. Project input has an explicit 20 MB JSON limit.
- 016: origin-scoped Web Locks permit one writer per project. Other tabs open
  read-only, receive saved revisions through BroadcastChannel, and can take over
  after the writer releases its lock. Taking over reloads the saved revision first.
  A startup epoch prevents an abandoned React mount from acquiring a writer.
- 017: `addMedia`, `updateMedia`, and `removeMedia` use portable validation and
  undo. Referenced media cannot be removed. Picked File resources are stored in
  IndexedDB separately from the JSON project. Identical path/content imports are
  deduplicated; reimporting the same identity restores its local resource.
- 018: the media bin shows source name, kind, known duration/dimensions, and
  available, missing, or unsupported status. File picking and drag/drop invoke
  the same local import action. Unsupported media remains visible with its error.

The browser adapter lives in `packages/platform-browser`. React owns one browser
session that connects this adapter to the existing portable coordinator. Project
switches flush pending saves before releasing the current writer. Session close
invalidates pending operations; old save callbacks cannot update a new session.

Fingerprints match Tandem's size/mtime/sampled SHA-256 format. Small files hash all
bytes; larger files hash their first and last MiB. Content matching ignores mtime
so copied files can retain their identity. This is a sampled identity, not a full
file integrity hash. Files with different source paths remain distinct.

Shared Input, Field, Label, Separator, and Alert components were generated with
the existing shadcn preset. Using `--path src/components` from `packages/ui`
avoids the Windows alias destination issue from the previous batch. MediaBunny
loads on demand for audio/video analysis instead of entering the initial bundle.

## Limits

Only Windows Chromium is verified. Firefox, Safari, macOS, Linux, mobile, native
Tandem reopen, and desktop packaging remain unverified. No new accessibility
scanner run was performed in this batch; controls use labels, native validation,
status/alert regions, and the shared accessible components.

These phases register and analyze media; they do not place or play clips. The
viewer explicitly reports unavailable preview for a populated imported project.
Timeline clip rendering, editing, playback, and video export remain later phases.

IndexedDB is scoped to browser profile and origin and may be cleared or evicted.
Downloads contain project data and source references, not media bytes. Source
files remain local. Portable archives and general relinking remain planned.
Restoration by reimport currently requires matching path and sampled content ID.
Conflicting files with an existing project ID are refused, rather than replacing
an existing saved copy. Project recovery UI and persistent undo history are later
phases. A browser without Web Locks receives an explicit editing error.

Import may store local resource blobs before its project batch commits. A failed
batch does not change the project, but can leave unreferenced local blobs for
future storage cleanup. Ordinary browser shutdown can interrupt pending work;
the interface warns on leaving during unsaved work and preserves the last
successfully committed snapshot.
