# Phases 061-066 verification

Verified on 2026-10-22 in Windows Chromium. The previous batch, phases 055-060,

## Reference and implementation

The baseline remains Tandem `735a9b8e162c1f951044baa892d94993869f2e77`.
`Sources/TandemRender/Effects.swift`, `FrameComposer.swift`, `LayerMath.swift`,
and `Sources/TandemCore/EffectRegistry.swift` were inspected locally. Their diff
against the pinned commit was empty. Attribution points to
`tests/fixtures/tandem/TANDEM-LICENSE` in the relevant ported wrappers.

The reference delegates spatial filtering to Core Image. Apple's
[sharpen-luminance documentation](https://developer.apple.com/documentation/coreimage/cisharpenluminance)
and [filter reference](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Reference/CoreImageFilterReference/index.html)
were consulted for parameter and pixelation-center semantics. Those APIs do not
provide portable shader implementations. The browser therefore uses explicit
portable kernels; matching native pixels remains unverified.

- Phase 061 implements luminance unsharp masking with strength `amount / 10`
  and the reference source-relative radius `1.69 * max(1, height / 1080)`.
  It preserves alpha and RGB channel differences. Enabled state, amount, reset,
  and animation use the existing registry inspector and commands.
- Phase 062 implements premultiplied-alpha Gaussian blur with source-edge
  extension. Numeric radius and keyframes resolve through the shared frame plan.
  Radius units are converted using output pixel scale divided by layer fit/scale.
- Phase 063 implements source-space pixelation with the Core Image default
  center at 150/150 in y-up coordinates, fractional sample centers, clamped
  source edges, and premultiplied bilinear sampling. Projected block sizes at or
  below one source pixel bypass processing.
- Phase 064 implements a colored shadow of the transformed foreground alpha,
  including its rounded crop and border. Offset uses the reference light-angle
  convention. Blur treats pixels outside the layer as transparent. Padding
  retains off-canvas pixels that can cast a shadow into the output. Opacity is
  applied to the combined foreground/shadow once.
- Phase 065 implements the reference rectangular border backing. It grows
  outside the cropped rectangle and follows rounded corners. Transparent holes
  show its backing color. Width scales with the output short side and remains
  independent of layer scale. Alpha-following cutout outlines still depend on
  the later cutout renderer.
- Phase 066 rounds the cropped layer before border and transform. Radius is
  limited by visible dimensions; the border's outer radius grows by its width.
  Shadows follow the resulting alpha.

`packages/core/src/spatial-processing.ts` owns portable Float32 raster kernels
and accepts browser-supplied scheduling/cancellation callbacks. It uses no DOM
or timer globals. `layer-styles.ts` owns output-unit scaling, colors, defaults,
first-enabled style selection, and shadow direction. The browser adapter owns
canvas clipping, composition, and padded shadow surfaces.

`platform-browser/color-processing.ts` keeps the source effects in floating
point between stages. Media looks run before clip color/spatial effects, in list
order. Style effects in media looks are ignored, matching the reference. Clip
styles have fixed stages: crop, rounded corners, border, transform, shadow,
then group opacity. The first enabled instance supplies each style. Preview and
export share this painter. Unsupported cutout and sound processing still fail
preflight. The inspector explains the order, and all six existing registry
sections now render their values.

## Automated checks and tolerances

`vp run check` passed formatting, lint, TypeScript, and **154 tests in 23 files**.
`vp run build` passed client, server, and prerender compilation. Existing bundle
size and TanStack circular-dependency warnings remain. Client entry and media
chunks are approximately 523 and 507 kB before gzip. The mechanical Impeccable
check ran once on the changed inspector and returned `[]`.

`spatial-processing.test.ts` covers constant-edge preservation, normalized
Gaussian impulses, broad-kernel symmetry, premultiplied alpha, transparent shadow
edges, sharpened edges, unchanged sharpening alpha, pixel-grid boundaries,
pixelation alpha interpolation, cancellation, cooperative scheduling, first-enabled
styles, defaults, light direction, output scaling, and animated frame-plan values.
The existing reference fixture now validates without a pending-blur warning.

Small Gaussian kernels, sigma at most 2, use normalized separable convolution
truncated at four sigma. Larger kernels use three sliding box passes to bound
processing cost. Independent 1D Gaussian impulse comparisons at sigma 3, 5, 20,
and 100 pass a maximum absolute error of 0.015. This is an impulse-kernel bound,
not a claim that every photograph differs by fewer than four channel values.
Float raster identity and alpha checks use tolerance 1e-6. Broad blur can change
in small steps as its box widths change during animation.

Sharpening is a documented luminance high-pass equivalent. Its exact response
has not been measured against CISharpenLuminance. No native macOS reference
images were available for these checks. Canvas geometry samples allow one
channel value of rounding, with edge antialiasing inspected separately. WebM
comparisons permit 12 channel values around these synthetic samples.

## Remaining limits

Only Windows Chromium was verified. Native Core Image pixel parity, native
Tandem reopening, Firefox/WebKit, other desktop systems, real touch hardware,
and a complete accessibility audit remain unverified. Phase 028's public-host
acceptance is still pending. No deployment was made.

The small-radius Gaussian, broad-blur approximation, luminance sharpening, and
chosen pixelation sampling model have the explicit limits above. Large source
rasters and padded shadow canvases can consume substantial memory and render
slower than real time. No GPU filter implementation or HDR color pipeline was
added. The renderer still uses RGBA8 canvas input/output around Float32 source
processing. Canvas antialiasing can differ from Core Image at rounded edges.

Cutout/matte processing and alpha-following cutout borders remain unavailable;
PiP presets that enable cutout still report that missing renderer. Manually
cropped and transformed PiP layers are supported, as exercised here. Titles,
graphics, adjustment clips, transitions, audio effects, mixing, and other later
phases remain pending. Existing project persistence, media portability, codec,
five-minute, 1080p, and 1-60 fps limitations remain. Interactive undo resets on
reload. The next phase is 067, adjustment clips.
