# Phases 126–130 verification

The [comments/jobs/archive follow-up](jobs-archive.md) supersedes the comment
context, sound-sync, recorder-default, watch-replay, analysis-wait and folder
archive gaps below. The [render/review follow-up](render-review.md) supersedes
the original validate/check limits. This report preserves the earlier baseline.

Implemented and exercised on Windows on 2026-10-24. These groups now have
baseline service adapters and a host-backed CLI. Full Tandem compatibility
remains open for the differences below. Phase 131 has not started.

## Review

`validate` returns the shared validator's revision, validity and issues.
`comments` returns timeline comment markers in time order with the clips playing
at each marker. Resolve a comment with `apply` and `removeMarker`; undo restores
it. Comment transcript context, reviewed revisions and review/activity navigation
are pending. `diff`/`restore` with `reviewed` still return an unsupported error.

`check` requires `quick:true`. It reports structural validation and subframe
clips/gaps, with zero rendered frames and an explicit capability warning.
Rendered black-frame/flicker/softness scans, speech-cut analysis and changed-range
checks return HTTP 501. This baseline does not claim a full reference quick scan.

## Sync, watch and wait

`sync` reads video-source delays and sets selected camera/media picture delay
through shared edits, with dry-run, revision checks and undo. Sound matching,
automatic placement and recorder defaults remain unsupported. `makeDefault:true`
or `files` returns HTTP 501. `defaultDelay:0` is accompanied by a limitation warning.

`watch` is a cancellable long poll after a revision, with a 30-second default
and a 600-second limit. It returns the current revision, `changed`, `generation`
and `resync:true`. There is no event replay log: `events` and `jobs` are empty;
read fresh queries after a change. Pass the returned generation when reconnecting
to detect replacement by a project with a lower revision. CLI `watch --follow`
does this automatically. Disconnecting removes the waiter without replaying edits.

`wait` observes existing editor jobs or UI exports and returns queued/running/
done/failed/cancelled items. Timeout returns unfinished items; cancelling the wait
does not cancel those jobs. It does not schedule missing analysis. Per-media
transcript/matte/proxy waits return HTTP 501. Timeout is currently capped at 600
seconds rather than the reference's 24 hours. One renderer RPC runs at a time,
so a concurrent service export can return HTTP 503 to another renderer request.
The existing host `status.jobs` does not include renderer job state; use `wait`.

## Resources

`effects` returns all 15 registry definitions, optional filtering by type, and a
`rendered` capability flag. Unknown types return HTTP 404. Reference transition,
layout and animatable-path catalogues are not yet included in this result.

`archive` writes a portable `.sidecut` ZIP under the profile's `exports` directory,
using the same resource collector as the UI archive action. It requires locally
available sources, preserves asset provenance and rejects existing outputs and
unsafe paths. It does not implement the upstream standalone-folder `to`,
`withCache` or dry-run semantics. Archives retain the existing 256 MiB limit.

`relink` takes a SideCut `mediaID` and `path` beneath the selected watched folder,
or the managed project folder when none is selected. It passes a bounded copy
to the existing identity/property checks and updates the same host coordinator.
The source limit is 64 MiB. Automatic directory searches, ambiguous-match reports
and dry-run relink are pending. No arbitrary renderer filesystem access is added.

## Asset library and segments

All eleven operations have adapters: `assets-providers`, `assets-search`,
`assets-fetch`, `assets-show`, `assets-use`, `assets-credits`, `assets-generate`,
`assets-install-starter`, `segments`, `save-segment` and `insert-segment`.

Catalogue search is offline by default. Online search requires `online:true`
and an explicit providers list. Fetching an uncached remote asset requires
`online:true`. Starter installation adds 90 metadata entries; downloading them
requires `online:true`. Generation requires `confirmedPaid:true` and uses the
existing provider transport and credential store. Secrets are not returned.
No provider downloads or paid generation were performed during acceptance.

`assets-use` adds existing normalized media/fonts/LUTs to the current project.
Timeline-placement/anchor/pop options return HTTP 501. It uses existing UI edit
labels/authorship. Credits include required and optional attribution text.
File results identify browser-library filenames, not native library paths.

Segments reuse the IndexedDB library and existing copy/insert workflow. Save
accepts clip IDs or a range; insert accepts a name/ID, time and placement mode.
Parameterized fields, replacement, native shared-library folders and complete
reference summaries remain pending. Existing segment behavior includes linked
partners. Library-only operations still require an attached desktop renderer;
standalone library processes and exact MCP mappings belong to subsequent work.

Renderer mutations use the existing shared coordinator. Do not automatically
retry a mutation after disconnect: it may have committed before the reply was
lost. The CLI never retries requests. The existing `apply` idempotency mechanism
remains available for explicitly repeatable edit batches.

## CLI usage

Start SideCut, then point the CLI at its profile discovery file. The file contains
credentials; do not publish it. `SIDECUT_API_FILE` also selects it. Default
discovery uses the packaged app's `sidecut` profile directory; development
profiles should be selected explicitly.

```sh
vp run cli -- --help
node scripts/sidecut-cli.mjs schema --endpoint-file /path/to/current.tandem.api.json
node scripts/sidecut-cli.mjs status --endpoint-file /path/to/current.tandem.api.json
node scripts/sidecut-cli.mjs check --quick --endpoint-file /path/to/current.tandem.api.json
node scripts/sidecut-cli.mjs assets search --text rocket --endpoint-file /path/to/current.tandem.api.json
node scripts/sidecut-cli.mjs segments list --endpoint-file /path/to/current.tandem.api.json
```

The CLI reads accepted fields/types from the authenticated host schema. Flags
accept kebab case, including acronyms such as `--media-id` and `--clip-ids`.
Arrays use JSON; `--input` reads a request file and `--request` takes a JSON
object. Commands accept `project`, `assets` and `segments` namespaces. Results
are JSON on stdout, errors on stderr. Exit codes are 0 success, 2 invalid input,
3 unavailable, 4 stale revision, 5 not found, 6 unsupported and 130 interrupted.

`new`, `open`, `import-edl` and `import-filmora` replace the active managed project
and require `expectedRevision`. Replacement checks generation/revision, saves
through the project store and retains its backup. `open` reads a `.tandem` source;
it does not launch a closed application. EDL files use the UI's `{edl,recipe}`
wrapper. Import paths are bounded by the selected folder, with a 20 MiB limit.
All edits pass through the host; the CLI owns no project coordinator.

Human-readable output, exact upstream flags/spellings, application launch,
installable binaries and an opt-in `tandem` alias remain pending. No executable
names or system PATH entries were changed.

## Evidence

- `tests/fixtures/tandem/review-library.json` pins 20 baseline requests and a
  synthetic comment/subframe fixture. Its provenance identifies the reference
  types and distinguishes SideCut adaptations from upstream responses.
- Core tests check malformed fields, comment clip context and subframe findings.
  Host tests cover CLI errors, shared revisions, replacement/import backups,
  sync dry-run/undo, watch timeout/cancel and generation-aware reconnect.
- Job tests use the actual scheduler to verify completion, failure, timeout and
  cancellation of a waiter while the underlying job continues.
- `tests/desktop/verify-adapters.mjs` runs the real Electron app and CLI. It
  creates/edits/inspects/exports a project, resolves a comment, observes changes,
  installs offline starter metadata, fetches/uses a local SVG, saves/inserts a
  segment, relinks a WAV through the host and writes a 772,407-byte archive.
  It asserts that remote fetch and unconfirmed
  generation are refused. See [runtime results](phases-126-130-runtime.json) and
  [the editor screenshot](phases-126-130-editor.png).

The runtime uses a dev server at `http://127.0.0.1:4270` and the built desktop
host. Run `vp run build:desktop`, unset `ELECTRON_RUN_AS_NODE`, then run
`vp exec --filter @sidecut/desktop electron ../../tests/desktop/verify-adapters.mjs`.
The script uses and removes a temporary Electron profile. It returns a nonzero
exit code on assertion failure. Windows development runtime is verified;
packaged installations, macOS and Linux are not accepted by this evidence.

Final checks: `vp run check` passed formatting, lint, all TypeScript programs
and 334 tests in 68 files. `vp run build:desktop` passed. The final runtime
record shows revision 6 in the CLI/editor, two timeline clips, a 546-byte WebM
for the 0.1-second solid fixture, and successful local asset/segment/relink
operations. Existing dependency/build and Electron safeStorage deprecation
warnings remain.
