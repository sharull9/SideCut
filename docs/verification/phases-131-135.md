## MCP

Run `node scripts/sidecut-mcp.mjs --endpoint-file /path/to/current.tandem.api.json`
with the desktop running. `SIDECUT_API_FILE` is also supported. The process uses
the official MCP TypeScript SDK's stdio server transport. Stdout contains only
protocol messages; startup failures go to stderr. Configuration example:

```json
{
  "mcpServers": {
    "sidecut": {
      "command": "node",
      "args": ["/absolute/path/side-cut/scripts/sidecut-mcp.mjs"],
      "env": { "SIDECUT_API_FILE": "/absolute/path/current.tandem.api.json" }
    }
  }
}
```

The adapter exposes all 43 names in the pinned inventory, including
`assets_search`, `assets_use`, `assets_show`, `assets_credits`, `assets_generate`,
`assets_providers`, `segments_list`, `segments_save` and `segments_insert`.
Tool input JSON Schemas come from the host's field definitions and required-field
lists. Host errors return text blocks with `isError:true`. Frames and screenshots
return PNG image blocks when the request returns inline image data. File-output
requests return metadata. MCP cancellation reaches the host request signal.

The SDK client test exercises actual stdio initialization, tool discovery,
shared edits, idempotent repetition, undo, malformed requests and cancellation.
Electron acceptance uses an SDK client to edit the live project, observe the
editor, undo and inspect a real frame. No second project coordinator is created
by the MCP server.

These are SideCut service schemas, not complete upstream schemas. Existing
resource, quality, transcription, review and asset limitations remain as
documented in earlier reports. Per-call upstream `project` path selection,
reference readable text, reviewed-state instructions and every tool's complete
upstream result shape remain pending. The server describes its actual supported
behavior rather than instructing clients to use unavailable review/scanning
features. Provider opt-in and paid-generation guards remain in place.

Implementation reference: [MCP SDK stdio documentation](https://ts.sdk.modelcontextprotocol.io/server).
Pinned names/behavior reference: `TandemAPI/MCPServer.swift` at revision
`735a9b8e162c1f951044baa892d94993869f2e77`. The MIT notice remains in the fixture folder.

## TypeScript client

`@sidecut/client` exports `SideCutClient`, `ServiceError`, schema-derived
`ServiceOperation`/`ServiceRequest`, and the existing command/batch types.
Required request fields, optional fields and primitive/array/time types derive
from the same definitions that validate HTTP requests. Query fields are also
shared with the host and CLI schema. Result values are `unknown`, so callers
must validate the data they use; full typed result decoding is pending.

```ts
import { SideCutClient, ServiceError } from "@sidecut/client";

const client = new SideCutClient({ port, token });
const options = {
  expectedRevision: revisionReadBeforePlanning,
  idempotencyKey: crypto.randomUUID(),
  label: "Update sequence metadata",
};
await client.apply(
  [{ updateProject: { patch: { metadata: { source: "typed client" } } } }],
  options,
);
```

The client does not retry automatically. Retain the exact commands, revision
and idempotency key to repeat an ambiguously completed `apply`. The host now
lets the coordinator return a known idempotent result before checking the old
revision. A genuinely new stale edit still returns HTTP 409 with the current
revision. The client test deliberately loses a committed reply, repeats it and
asserts one revision, then checks a distinct stale request.

`scripts/client-bulk-example.mjs` shows the read/plan/apply and conflict pattern.
It edits the active project's metadata when run. Source exports work in this
workspace's bundler and Node 24's erasable-TypeScript loader; publishing a built
SDK and matching every reference convenience method remain pending.

## Export queue and presets

The Export dialog queues up to five WebM/WAV outputs and renders one at a time.
It displays progress, cancellation and failure details, and retains download
links across dialog close/reopen. Remove completed exports to release their
object URLs; closing/replacing the project clears the queue. Completed downloads
share a 256 MiB memory limit. The queue is session-local and is not persisted
across application restarts.

Preset controls expose main canvas, 720p review, 1080p, portrait WebM, alternate
project formats, and 48 kHz stereo PCM WAV. Unit tests check preset dimensions;
the runtime exports WebM and a 384,044-byte two-second WAV. Existing HTTP
H.264/AAC/WebM export paths are unchanged. 4K HEVC, exact reference codec/quality
settings, persistent/export-service queues and the complete native preset matrix
remain pending. Browser output retains the five-minute, 1080p/portrait limits.

Queued exports retain their requested revision. If the project changes before
one starts, it fails with a message to queue it again. Unit tests verify ordering,
failure, cancelling queued/running work and releasing completed entries. WAV
progress currently reports running/completed rather than intermediate progress.

## Keyboard and pointer interactions

The default **Premiere subset** layout uses implemented bindings from the pinned
`premiere.json`; **Editing only** keeps edit shortcuts while leaving ordinary
navigation keys to the browser. The selection is session-local.

- Ctrl/Cmd+Z and Shift+Ctrl/Cmd+Z undo/redo; Ctrl+Y also redoes.
- Ctrl/Cmd+B or K splits; Delete lifts; Shift+Delete ripple-deletes.
- Ctrl/Cmd+C/V copies/pastes selected clips with fresh clip/link IDs. Paste is
  one atomic edit and undo step. This clipboard is internal to the same project.
  Clips with transitions are refused with a saved-segment alternative; external
  OS clipboard and cross-project resource copying remain pending.
- Space toggles playback; Left/Right steps frames; Shift steps five frames.
  Up/Down navigates edit boundaries, Home/End navigates the sequence, comma/period
  nudges selected clips and I/O sets a timeline range.
- Input, select, contenteditable, dialog and menu focus is protected. Composition,
  already-handled keys and repeating destructive keys are ignored. Local trim
  and separator controls retain their own arrow-key handling.
- Drag empty space on a track to select intersecting clips and linked partners.
  Shift-drag sets a time range. Escape/cancel restores selection. The marquee
  currently works within one track, rather than across track rows.
- Track resize separators support pointer input, arrow keys and reset. Ctrl/Cmd
  temporarily bypasses edge snapping during clip drags. Ctrl/Cmd+wheel zooms the
  timeline. Clip drags scroll horizontally near the viewport edges while pointer
  movement continues; stationary-pointer autoscroll is pending.

Runtime acceptance uses Electron keyboard/mouse events for clipboard/undo,
input-focus protection, track resizing, marquee selection and shift-drag ranges.
Full custom keymaps, context menus, OS clipboard, all tools/shortcuts and complete
pointer parity remain unchecked in the adapter inventory.

## Accessibility and compact desktop windows

The desktop minimum width is now 640 pixels. On narrower layouts the inspector
and media panels collapse to their existing rails. Below 760 pixels, opening
one side panel collapses the other. Existing panel show/hide focus restoration
is retained. The header grows when controls wrap; the editor itself does not
overflow horizontally at the tested 680-pixel content width. Timeline content
keeps its own horizontal scrolling. Export content scrolls within the viewport.

Acceptance checks the export dialog's close/focus-return path and all header
controls' bounds. An axe WCAG 2 A/AA and 2.1 AA scan of the compact editor reports
zero violations. The report retains incomplete findings for manual review; this
is not a complete accessibility certification or a screen-reader test. Track and
transcript lanes now have group semantics for their accessible labels.

The Impeccable detector flagged the existing track-header color stripe. It is
retained as an incumbent track-type indicator. No redesign or visual-system
replacement was made. Real touch/mobile editing, screen readers, platform high
contrast, and full reduced-motion/keyboard coverage remain unverified.
