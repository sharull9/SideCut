# Phases 067-072 verification

Verified on 2026-10-22 in Windows Chromium. Phases 061-066 were committed as
`eb37139` before this batch. These six phases remain uncommitted for review.

## Reference and implementation

The baseline remains Tandem `735a9b8e162c1f951044baa892d94993869f2e77`.
`Sources/TandemRender/RenderPlan.swift`, `Transitions.swift`, and
`FrameComposer.swift` were inspected in the local reference checkout. Their diff
against the baseline was empty. Transition editing was checked against
`TandemCore/Editing.swift` and `TransitionSounds.swift`. Ported modules reference
`tests/fixtures/tandem/TANDEM-LICENSE`.

- Phase 067 applies adjustment effects to the composite below that clip's track,
  then blends the result using adjustment opacity. Higher tracks remain unaffected.
  Transform, crop, and layer styles do not apply to adjustment content, matching
  the reference. The toolbar inserts an adjustment on an existing unlocked track
  or a new top track. The inspector exposes opacity and source effects.
- Phase 068 adds atomic transition creation, patching, and removal, with revision
  checks, journal replay, and undo/redo through the existing coordinator. Commands
  validate type, direction, IDs, positive duration, same-track references, touching
  cuts, occupied edges, clip lengths, and track locks. Missing source handles
  produce warnings and hold edge frames. Timeline blocks expose a duration drag
  handle and a dialog with numeric controls. Escape cancels a drag. Single-edge
  windows on existing imported or trimmed clips clamp to the clip duration.
- Phase 069 implements dissolve and both black fades. Two-clip windows center on
  the cut, extending source lookup through the handles. Dissolve mixes
  premultiplied alpha; black fades darken RGB while retaining layer alpha.
  Single-edge fades span their full window, while a two-clip fade reaches black
  at the midpoint. Overlapping windows fold into nested picture nodes so each
  source layer is drawn once.
- Phase 070 implements push and slide in four directions. Push moves both sides;
  slide leaves the outgoing side stationary and moves the incoming side. A
  one-sided slide exit stays visible until its clip ends, matching the reference.
  Empty canvas regions expose lower tracks.
- Phase 071 implements cut-slide, wipe, and zoom with the reference easing,
  geometry, directions, and window rules. Cut-slide uses quartic ease-in/out;
  other geometric transitions use cubic ease-in/out. Wipe has a 6% soft edge.
  Zoom scales the outgoing image from 1 to 2 and incoming from 2 to 1, with its
  crossfade concentrated between eased progress 0.35 and 0.65. Motion and zoom
  blur use nine-tap portable approximations, not Core Image's private kernels.
- Phase 072 shares audible segment selection between frame planning, preview,
  and export. Muted/hidden tracks, disabled/muted clips, held frames, and sources
  without audio are excluded. Only audible solo tracks activate solo mode.
  Real source bounds trim audible ranges, preserving silence outside those
  bounds. Preview schedules each clip against one audio clock. Export mixes
  independent decoded streams into bounded 48 kHz planar stereo blocks,
  duplicates mono, linearly resamples, and emits silence in gaps. Overlapping
  clips and tracks sum without an automatic gain adjustment.

Generated transition sounds, automatic sound synchronization/removal, audio
crossfades, gain/fade processing, loudness normalization, audio effects, and
pitch-corrected speed changes remain later phases. Unsupported processing fails
preflight. A transition tied to an existing sound clip must be untied before its
timing changes or removal; untie preserves the sound clip.

## Browser evidence

T3 preview status/open succeeded, but two snapshots returned
`Preview automation snapshot timed out after 15000ms.` Verification therefore
used `vp exec agent-browser` in isolated browser sessions.

With a development server on port 3030, the reusable native browser fixture
`tests/browser/transitions-audio.js` was imported through
`/@fs/<absolute-repo-path>/tests/browser/transitions-audio.js`.
Call `verifyTransitions()` and `verifyTimelineAudio()` to rerun the checks.
Playback needs a browser user activation. `verifyTransitions({saveFixture:true})`
also stores the picture fixture in a fresh browser profile; it deliberately
refuses to overwrite a different saved project with the same ID.

Picture checks passed for all eight transition types in all four directions at
the beginning, midpoint, and end of a cut. Slide, cut-slide, wipe, and zoom also
passed four-direction single-overlay entry/exit assertions over a green lower
track; push passed its lower-track checks. Solid geometry assertions allow two
channel values of canvas rounding, or three near an overlay exit. This verifies
the documented portable behavior, not native Tandem reference pixels.

An exposure adjustment with opacity 0.5 changed the lower red sample to
`[76,0,0,255]`, leaving a higher green layer `[0,255,0,255]`. Native WebM decoding
returned `[75,0,0,255]` and `[0,255,1,255]`. A separate dissolve export was 1,918
bytes. At 0.5, 1, and 1.5 seconds, decoded samples were `[255,1,0,255]`,
`[128,0,127,255]`, and `[1,0,255,255]`, within one channel value of preview.
The encoded assertions permit 12 channel values to account for codec loss.

The synthetic mono PCM fixture has two 400 Hz pulses at different source offsets.
Two timeline tracks align those pulses at 0.1 seconds. Raw mixed RMS was
0.1414166; decoded WebM RMS was 0.1408159. A lone later pulse measured 0.0715011.
Decoded gap RMS was below 0.000182, against a 0.003 silence threshold. The 9,538
byte export preserves the aligned pulses and gaps. Level comparisons allow
0.02 RMS codec error. Real AudioBufferSourceNode calls placed both initial
tracks on the same clock within one 48 kHz sample. Seeking to 0.12 seconds
scheduled source positions 0.22 and 0.62, including decoded packet timestamps,
within 0.002 seconds. Muted solo material did not play.

The normal UI inserted an adjustment, added its color effect, and opened its
parameter controls. The transition dialog changed a duration from 1 to 0.6
seconds. A real pointer drag changed it to approximately 0.8 seconds, and the
dialog displayed that saved value. The handle's visual span now stays centered
on a paired cut while dragging; a tail handle sits at the left edge.

used the same browser adapter through the development build.

## Remaining limits

Only Windows Chromium was verified. Native Tandem reopening and pixel parity,
Firefox/WebKit, other operating systems, real touch hardware, and a complete
accessibility audit remain unverified. Phase 028's public-host acceptance is
still pending. No deployment was made.

Cut-slide and zoom blur are approximate. Canvas uses RGBA8 surfaces and may
round or antialias differently from Core Image. Transition/adjustment groups
allocate full-frame canvases and can cost substantial memory and CPU at large
sizes; no GPU or HDR pipeline was added. Audio export currently uses the first
two channels of sources with more than two channels, without a surround downmix.
Summed peaks can clip at playback or encoding until later gain/limiter phases.

Existing media portability, codec, five-minute, 1080p, and 1-60 fps export limits
remain. Interactive undo resets on reload. Cutout, titles, graphics, and later
sound processing remain pending. The next phase is 073, gain and fades.
