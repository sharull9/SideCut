## 136: Browser compatibility

`scripts/verify-browsers.mjs` serves the built SPA on secure loopback and runs
the same journey in Playwright Chromium, Firefox and WebKit. It imports a
project, copies/pastes clips, waits for the saved state, reloads, imports and
places PCM audio, downloads the project, exports WebM/WAV, and archives/reopens
the project with its source copy. It uses fresh browser contexts and no provider
network calls. Waiting for the saved indicator is required before reload.

| Engine on Windows      | Persistence and editing                                | Media/export                                                             | Acceptance                                                             |
| ---------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| Chromium 156           | Import, copy/paste, saved reload, archive/reopen pass  | PCM import, VP8/Opus WebM and stereo WAV pass                            | Tested loopback journey passes                                         |
| Firefox 157            | Same journey passes                                    | Same exports pass                                                        | Functional journey passes; recoverable React hydration warnings remain |
| Playwright WebKit 27.2 | Project editing/reload and resource copying are tested | This Windows port lacks `AudioBuffer`, `AudioEncoder` and `VideoEncoder` | Full media journey is unsupported; not accepted                        |

See [machine-readable browser results](phase-136-browsers.json) and the
[Chromium](phase-136-chromium.png), [Firefox](phase-136-firefox.png) and
[WebKit](phase-136-webkit.png) captures for exact versions, errors and results.
The runner returns a nonzero exit status while any engine is not accepted.
An unsupported export is recorded as a failure of browser acceptance, not a
passing fallback. WebKit is not evidence for Safari on real macOS/iOS.

Testing found that the WebKit Windows port rejects IndexedDB `Blob/File`
values. Project-resource storage now retries that specific cloning failure
with an ArrayBuffer and file metadata; reading reconstructs the original File.
Existing File records still work. Quota and unrelated storage errors propagate
without a fallback. A focused test checks byte/name/type/modification-time
preservation. The actual WebKit import journey verifies the fallback. Media
readers now report missing Web Audio support explicitly instead of throwing an
unhelpful missing-global error. Asset-library Blob storage is not covered by
this project-resource fallback.

Limits apply independently to every browser: sequence exports remain capped at
five minutes and 1080p/portrait; project archives at 256 MiB; retained downloads
at 256 MiB across five queue entries. IndexedDB/Web Locks are used for browser
persistence; storage eviction and crash-before-save are not accepted. Firefox
and WebKit do not expose the directory picker in this run. First-run model
downloads, storage pressure, file-picker permissions and model memory ceilings
were not measured. A public hosted deployment, real Safari, mobile hardware
and browser/OS combinations beyond this Windows run remain unverified.

Reproduce after `vp run build:web`:

```sh
vp exec playwright install chromium firefox webkit
vp run verify:browsers
```

The harness uses an isolated local production server and removes its downloaded
test files afterward. No running dev server is required. The restored dev server
at port 4270 remains available for the earlier Electron development checks.
T3 preview snapshots timed out twice, so these browser checks used Playwright.

## 137: Windows delivery

The package now produces a per-user NSIS installer and includes
`resources/cli/sidecut.cmd` plus the dependency-free CLI script. The launcher
uses the packaged Electron executable in Node mode; no separate Node installation
or PATH change is required. It accepts the same discovery-file/JSON options as
the repository CLI. Existing SideCut installations are not replaced by the test.

`scripts/verify-windows-install.ps1` silently installs into a temporary directory
with spaces and Chinese characters, exercises the actual installed executable
and CLI launcher, then uninstalls and removes that directory. Acceptance uses
a separate Unicode/space profile and verifies:

- Renderer isolation: no `process` or `require`, validated preload bridge present.
- Import, shared edit/save, shipped FFmpeg/FFprobe, VP8/Opus export and WAV decode.
- Archive creation with the local source copy and project reopen after app exit.
- Encrypted credential write/decrypt round trip using a synthetic test value;
  plaintext is absent from the stored encrypted file and the test value is cleared.
- Refusal of a second project-store lock and the installed CLI's help output.

The final [installed Windows result](phase-137-installed-windows.json) is copied
from the release verifier. The installer and uninstaller are unsigned and use
Electron's default icon. Windows SmartScreen/reputation, updating an existing
installation, signing and distribution to other machines are not accepted.
No release was published. Installer files remain under the ignored
`apps/desktop/release` directory.

```sh
vp run package:desktop
vp run verify:windows-install
```

`verify:packaged` also checks the unpacked app, and accepts an explicit
`--executable` path for installed verification. It clears development renderer
and media-binary overrides, uses a disposable profile, tests reopening and the
bundled CLI, and returns nonzero on failure. The packaged smoke test was updated
to use the current export queue rather than the removed Render WebM button.

## 138–139: macOS and Linux delivery

These phases are prepared but **not accepted**. This host is Windows; its only
WSL distribution is Docker Desktop's environment and its Linux daemon is not
running. No native macOS runner is attached. The repository's delivery workflow
had no completed runs when checked. No remote workflow was dispatched for this
uncommitted workspace.

The native packaging path now includes a CLI shell launcher for both platforms.
The delivery workflow includes Windows x64, Linux x64 and Apple Silicon macOS,
with Node 24.22.1 matching the repository engine. It builds installers, checks
the unpacked app, then runs the target OS installation script before uploading
installer and verification artifacts.

- `scripts/verify-macos-install.sh` mounts the built DMG read-only, copies the app
  to a disposable Unicode/space installation path, checks its ad-hoc code
  signature and runs the installed verifier. It detaches before deleting its
  temporary directory. Developer ID, notarization, Gatekeeper, microphone/file
  permissions and real-user keychain prompts remain open.
- `scripts/verify-linux-install.sh` refuses an existing SideCut package, installs
  the built Debian package, resolves its executable, runs verification and removes
  the test package. The CI step uses Xvfb. AppImage installation/execution,
  Wayland, additional distributions and real desktop keyring/session behavior
  remain open. The credential check reports secure-keyring unavailability on
  Linux and refuses a plaintext fallback.

Both scripts pass shell syntax checks on this host. That is not native execution
evidence. They must run on the target systems before their roadmap acceptance
boxes can be checked. Hosted runner labels follow the
[GitHub runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
