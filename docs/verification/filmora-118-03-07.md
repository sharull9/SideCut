The next batch adds transitions, titles/nested templates and the first three
project queries. See [118.08–120.03 verification](filmora-queries.md) for current
acceptance; statements below about those features being pending are historical.

Verified on Windows on 2026-10-24 against the mapping rules in Tandem revision
`735a9b8e162c1f951044baa892d94993869f2e77`. These five subphases extend the existing
importer. Transition mapping and titles/nested templates remain open.

## Supported behavior

118.03 reads ZIP entries and unpacked folder metadata through the same portable
importer. The editor's **Filmora folder** picker accepts a parent containing
`ProjectFolder`, `ProjectFolder` itself, and `.wfp.dir` folders. The desktop
`import-filmora` operation accepts those directories within its selected source
root. Timeline `extra.json` markers retain time, name and comment. Clip/other
timeline markers are reported as unsupported; beat-detection data is ignored.
Ambiguous project metadata, invalid JSON, unsafe paths and negative marker times
reject the import. Desktop metadata junctions cannot escape the selected folder.

118.04 classifies source roles using Filmora resource hints, stream metadata and
the same filename/folder rules as the desktop scanner. A shared source keeps both
picture and sound capabilities. Track names follow content, with unique names for
extra lanes. Linked sound tracks follow their picture tracks. Overlaps become
extra lanes; gaps/overlaps within one millisecond close at the next clip's start.
Picture and sound link by map ID or recording base name and the same time range.
Video mute becomes hidden, audio mute remains muted, and locks apply after clips
are placed. Take tracks use cut ripple mode; others follow.

118.05 maps transform position, width scale, rotation, static crop, opacity and
cutout. Transform and opacity keys convert source clocks into clip clocks using
source offset and speed. Still-image animation retains Filmora's virtual source
clock even though the still clip starts at source zero. Nearest keys outside a
trimmed range remain available for interpolation. Crop/pan/zoom scripts become
transform settings or linear keys. Stretching retains width scale and emits an
approximation note. Unsupported blend modes, corner settings and in/out animation
emit warnings. Malformed animation or invalid crop dimensions reject the import.

118.06 maps basic colour, exposure/brightness, HSL, vignette and LUT metadata,
plus shadow, border and sharpen. Every use of a source must have the same grade
before it moves onto the source's shared look. Differing grades stay on clips;
border and shadow remain clip effects. Disabled effects are ignored. Unsupported
non-default settings are reported. Existing effect schemas/renderers remain the
authority after import.

118.07 preserves gain and Filmora auto-normalization at -24 LUFS with its loudness
gain added. Speech defaults to the project's -20 LUFS with zero gain, including
all sound on a track classified as speech. The portable option `keepLevels: true`
and desktop CLI flag `--keep-levels` preserve imported levels. Fades are in seconds,
capped to the final clip duration. Negative fades reject the import. Denoise and
voice enhancement map approximately to voice isolation. Balance, ducking,
unsupported audio effects and volume automation are reported when active.

Imports still build through one validated coordinator batch before replacing the
active project. Malformed metadata and stale host revisions preserve the active
project. Source files are referenced without being copied or probed by this
folder importer; users relink them through the existing resource workflow.

## Reproduction

```powershell
vp run check
vp run build:desktop

# Start in a separate terminal from apps/web:
vp dev --host 127.0.0.1 --port 4270 --strictPort

# From the repository root:
vp run verify:filmora
```

The runtime script uses fresh browser contexts and a disposable Electron profile.
It removes its temporary folder afterward. It makes no provider/model calls and
does not change the normal application profile.

For the host CLI, choose a source path inside its configured media root and pass
the current revision:

```powershell
vp exec node scripts/sidecut-cli.mjs import-filmora --path "project.wfp.dir" --expected-revision 4 --keep-levels
```

## Limits

These are synthetic import/persistence checks derived from the pinned Swift
source, not outputs recorded from running Tandem. No real Filmora installation,
macOS Tandem round trip, render pixel comparison or imported mix metering ran.
Cutout/voice-isolation settings are retained; no model quality/performance claim
is added. LUT files still need their resources to render. The fixture intentionally
references missing media and contains no private footage.

Transitions, titles, nested templates, reverse/freeze behavior, exact speed ramps,
unsupported colour/effects, blend modes and volume automation retain their
recorded gaps. Browser folder metadata and desktop project imports have a 20 MiB
limit. Browser ZIP imports and portable expanded entries retain the existing
256 MiB/10,000-entry limits. No native macOS/Linux, Safari/WebKit or installed
release verification ran for this batch. Full Filmora parity remains open.
