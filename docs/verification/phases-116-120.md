Verified on Windows on 2026-10-24. This batch implements portable archives,

HTTP transport and four project query adapters. Full Filmora mapping and exact
Tandem timeline-text parity remain pending. Phase 121 has not started.

## Archive and relink

`Archive project` creates a `.sidecut` ZIP containing a validated project
snapshot, a resource manifest and local source/library copies. Media and LUT
paths become relative. Asset attribution and licence copies are retained.
Registered library fonts are installed when the archive opens. Missing media,
LUTs or required library resources stop archive creation rather than producing
an incomplete backup. Existing extra resources are included, so the archive
can be larger than the currently visible timeline.

Each archive open creates an independent project ID at revision zero. Clip and
media IDs, edits and project metadata survive; undo history does not. This
avoids overwriting another saved project or replaying journal entries with old
paths. Resources are staged under the new ID before publishing the project.
Interrupted imports can leave unused resource copies but cannot overwrite the
original project's sources.

Archives have a 256 MiB compressed/expanded limit, 10,000 entries and bounded
relative entry names. Absolute paths, traversal, duplicate names and missing
manifest resources are rejected. Contents are never extracted into arbitrary
filesystem paths. Files selected for relinking are copied through the existing
resource store. Fingerprints ignore modification-time differences but compare
the stored size/content identity, and known kind, duration and dimensions must
match. Sources without fingerprints use the available media properties and show
a warning about that weaker match. A validated shared edit updates the existing
media ID and participates in undo.

Directly installed global fonts that have no project library record are not
automatically collected. Native sources still use renderer IndexedDB copies,
so a source must be present there to archive it. Archives are SideCut's portable
format, not a claim of compatibility with Tandem's folder archive manifest.

## Imports

`Open project` accepts `.tandem`, `.sidecut`, `.wfp` and JSON containing explicit
`edl` and `recipe` objects. For example:

```json
{
  "edl": { "segments": [{ "start": 10, "end": 12, "layout": "screen", "screen_offset": 0.25 }] },
  "recipe": {
    "name": "Example",
    "takes": [{ "start": 0, "camera": "camera.mov", "screen": "screen.mov" }]
  }
}
```

EDL source paths and an optional recipe `root` must be relative. Explicit recipe
settings, take clocks, segment order, linked camera/voice, screen offsets, PiP,
cut adjustments, layout overrides, B-roll and timeline overlays are supported.
Segments crossing a take boundary are shortened with a report entry. Invalid
ranges reject the import before replacing the current project. Intro,
transitions, inserts, sections, music and SFX recipe families are reported as
unsupported. Source files are relinked through the editor.

The Filmora baseline reads zipped WFP `ProjectFolder/project_info.json` and
`Medias/<id>/timeline.wesproj`. It preserves canvas/frame rate, track ordering,
mute/lock state, basic media clips, inclusive 100 ns timing, source offsets and
uniform speed curves. Resource filenames take precedence over clip filenames.
Missing media remains as references. Speed ramps use their average speed with
a warning; reverse/freeze clips are omitted with a warning. Effects,
transitions, transforms, titles and nested timelines are reported as unsupported.
Unpacked WFP folders and their `extra.json` markers remain pending. These mapping
families are split into follow-ups in the adapter plan, as phase 118 permits.

Both importers build projects through `ProjectCoordinator.apply`, with one
validated batch and an import report persisted in project metadata. This is
initial import coverage, not full upstream Filmora or recipe parity.

## Local service and queries

The desktop host starts HTTP on `127.0.0.1` with a random port and 256-bit bearer
token. The profile's `current.tandem.api.json` advertises the port, token, PID and
API version. It is written with owner-only permissions where the OS supports
that mode and removed on orderly shutdown. The renderer bridge never exposes
the token. Requests with browser Origin headers, cross-site fetch headers or an
unexpected Host are rejected. Requests have size, time and concurrency limits;
shutdown and client disconnects cancel in-flight native probes.

`GET /v1/health` is unauthenticated. `GET /v1/status`, `/v1/media`, `/v1/timeline`
and `/v1/clips` use default arguments; `POST` accepts an `application/json` object.
Errors use `{ "error": { "code", "message" } }`, with revisions where relevant.
Unknown operations and filesystem-output arguments are rejected. The only HTTP
mutation in this batch is `media` with `refresh: true`.

Status returns the host project revision, saved revision, dirty state, counts,
format and shared undo/redo labels. Timeline supports half-open time filtering,
JSON, compact text and summaries. Clips supports track ID/name/label, media
ID/path/basename, range filtering and `idsOnly`, in video-top-to-bottom then audio
order. Times accept seconds or colon-separated strings. Media reports usage,
disk existence and host analysis availability. Refresh scans the selected watched
folder, probes new files and commits a single revision-checked batch through the
same host coordinator as the UI. A missing folder, failed probe or stale project
does not partially commit; undo removes imported media.

Full query compatibility remains open: text formatting and non-default setting
annotations are not an exact port of `TimelineDump.swift`; words, renderer
analysis/jobs/exports, font warnings and review state are not connected to the
host service. Status explicitly warns about the host's limited view. Media disk
existence is independent of an available renderer IndexedDB copy. Symlink or
out-of-root sources are not read. `media.refresh` imports new files; the existing
folder watcher continues handling changes and copying bytes to renderer storage.
CLI and MCP adapters are not included.

## Evidence

- `vp run check` passes formatting, lint, every TypeScript program and 314 tests
  in 63 files. Interchange tests cover missing/traversing archives, resource and
  credit preservation, EDL clocks and failures, Filmora ticks/speed and failures.
  Browser session tests cover archive restoration and identity-checked relink
  with undo. HTTP tests cover all four query fixtures, authentication/origin/host
  rejection, bad input/oversized bodies, atomic refresh, undo and stale-project
  rejection. Synthetic query contracts are pinned in
  `tests/fixtures/tandem/project-queries.json`.
- `vp run build:desktop` builds the production renderer and desktop bundles.
- `tests/desktop/verify-interchange.mjs` runs the shared code in actual Windows
  Electron/Chromium with a local dev server. Its [runtime results](phases-116-120-runtime.json)
  confirm browser-to-desktop and desktop-to-browser archives retain all 768,078
  source bytes and the timeline clip without original paths, HTTP status/clips
  read that same project, an unrelated origin receives 403, and EDL/Filmora
  imports preserve the tested source offsets and speed. The editor toolbar fits
  a 1280-pixel content area. The script requires `vp dev --host 127.0.0.1 --port
  4270 --strictPort` from `apps/web` and unsetting `ELECTRON_RUN_AS_NODE`.
- The existing `tests/desktop/verify.mjs` also passes against the production
  build. Its [new production results](phases-116-120-production-native.json)
  retain sandbox isolation, shared-window revisions, stale-edit rejection,
  disk reopening, folder import/update and VP8/Opus timeline export.

The collaborative preview snapshot timed out twice, so runtime verification used
the repository's Electron workflow. Existing dependency directive, circular
route-generator, CommonJS preload and Electron safeStorage deprecation warnings
remain. macOS, Linux and packaged installers were not checked in this batch.
No live credentials or paid provider calls were used.

Reference semantics come from cached Tandem source at revision
`735a9b8e162c1f951044baa892d94993869f2e77`, with the retained MIT notice at
`tests/fixtures/tandem/TANDEM-LICENSE`. The WFP and query fixtures are synthetic.
