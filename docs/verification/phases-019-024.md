# Phases 019-024 verification

Verified on Windows with Headless Chromium 156 on 2026-10-21. Reference behavior
remains pinned to Tandem `735a9b8e162c1f951044baa892d94993869f2e77`.

## Implemented

- 019: `addTrack`, `removeTrack`, `moveTrack`, and `updateTrack`. Adds/moves clamp
  indexes within their track kind. Track references resolve by ID or unambiguous
  case-insensitive name. Locked tracks reject removal and placement; moving a
  locked track and changing its flags remain allowed, matching the reference.
  Headers expose add, rename, lock, mute, ripple mode, move, and remove controls.
- 020: `insertClip` in `place` mode, with stable explicit clip IDs, sorted clips,
  created-ID results, overlap/content/source validation, and atomic undo. Bin
  items drag to compatible tracks, snapping placement to the project frame grid.
  Place at playhead provides a keyboard-accessible alternative. Still images use
  a five-second initial duration; other sources need a known positive duration.
- 021: project-derived track and clip blocks, pixel-scaled ruler, internal
  scrolling, zoom in/out, and Fit. Track headers stay visible during horizontal
  scrolling. Clip locations and playhead positions share the same pixels/second.
- 022: single selection, Shift/Ctrl/Command multiselection, toggle selection,
  Escape/clear, pointer ruler seeking, keyboard Home/End and frame stepping.
  Clip selection replaces sequence settings with visible source-range details.
  Fractional-frame stepping uses integer flick arithmetic rather than repeated
  sample-rounded increments. Timecode display uses nominal non-drop frame labels.
- 023: local MediaBunny decoding into a source-preview canvas, including still
  images and nonzero source-in values. Frame retrieval uses the source timestamp
  and rejects stale results after a superseding seek. Preview closes readers on
  project change and viewer/session teardown. It never fetches source bytes from
  an external service. Output canvas resolution is capped at a 1280-pixel long edge.
- 024: play, pause, resume, seek while playing, and stop at sequence end. The
  transport advances from Web Audio time outside React. Decoded audio buffers
  schedule against that same clock, respecting source-in, clip range, gaps,
  mute, and solo flags. Seek/pause stop pending sound and invalidate old work.
  Navigation away releases the viewer's audio context; a hidden page pauses.

All edits use the existing coordinator and IndexedDB save queue. Zustand 5.0.15
is pinned in the workspace catalog and holds only transient view state. There
is no second mutable project copy in the UI. Selection/zoom/playhead reset on a
full page reload; selection and position reset when opening a different project.

Behavior was checked against `Editing.swift` and `ProjectQueries.swift` in the
cached pinned upstream checkout. Ten command families now have implementations;
overwrite/ripple insert modes explicitly reject until their later phases.

## Browser verification

Tested at `http://localhost:3000/`. T3 preview navigation succeeded, but both
snapshot attempts returned `Preview automation snapshot timed out after 15000ms.`
Browser checks continued with `vp exec agent-browser`.

The initial imported VP8/Opus recording demonstrated placement and playback.
It has a delayed first picture timestamp, so seeking before that timestamp
correctly produces no picture. For precise assertions, a second synthetic fixture
encoded 64x64 red, green, and blue frames at timestamps 0, 0.5, and 1 second with
MediaBunny CanvasSource. A separate generated two-second 48 kHz WAV contains a
440 Hz tone. No private footage, camera, microphone, or remote media was used.

- Opened a synthetic project with video and audio clips beginning at timeline
  0.25 seconds, each lasting 0.75 seconds, both with source-in 0.5 seconds.
- Stepped eight project frames to timeline 0.266667 seconds. Source preview
  selected timestamp 0.5 and produced center pixel `[2, 255, 1, 255]`, confirming
  the expected green frame. Both timecodes displayed `00:00:00:08`.
- Selected picture and sound with Shift-click; the inspector displayed two
  selected clips. Single selection exposed the source-in/range details directly
  inside the visible inspector at 1280x720.
- Played the fixture. Web Audio scheduled nineteen decoded buffers totaling
  exactly 0.75 seconds; their measured RMS was about 0.065. The first/last
  packets were cropped to the requested source range. The transport stopped at
  timeline 1.0 seconds, showing the expected blue source frame at timestamp 1.
- Sampled displayed playhead against actual AudioContext time during playback.
  Across 102 moving samples, clock-offset spread was about 10.7 ms. Thirty
  samples in the middle of the green interval displayed source frame 0.5.
  This is short-fixture evidence, not a general performance benchmark.
- Paused at about 0.311 seconds and confirmed the playhead remained still.
  Resumed, clicked the ruler with a real pointer while playing, and confirmed
  playback continued from the sought range and stopped at sequence end 3.5.
- Dropped a bin source at timeline 2.0 seconds on Picture. At 60 px/s, its block
  began at 120 px with 90 px width for 1.5 seconds. Zooming to 90 px/s changed
  those to 180/135 px. Fit preserved the same position/time relationship.
- Undid and redid that drop; one history step removed/restored one clip.
- Added a video track, renamed it, moved Picture above it, removed the added
  track, and restored it with Undo. Lock/mute flags and all three clips survived
  reload through actual IndexedDB storage.
- Dropping audio on a picture track left revision and clips unchanged and
  reported the incompatible source. Adding an overlapping picture layer made
  playback report unsupported compositing; Undo recovered the normal preview.
- Navigating to diagnostics while playing closed the actual AudioContext. Unit
  tests separately verify media-reader close and stale-frame cancellation.
- At 1280x720 and 1920x1080, document scroll dimensions matched the viewport.
  Timeline and inspector scroll internally. No browser page errors were reported.

## Limits and next work

Only Windows Chromium is verified. Firefox, Safari, other operating systems,
mobile layouts, desktop packaging, native Tandem reopen, and long/heavy project
performance remain unverified. No accessibility scanner was run in this batch.

This is source preview, not the full render pipeline. It supports one active
picture and one active audio source. Overlapping visual layers or audio mixing,
non-media content, transitions, effects, keyframes, speed changes, freezes, edge
holds, and clip-property processing reject with a visible message. Even explicit
neutral property objects may require a later render-capability implementation.
There is no proxy/prebuffer pipeline or long-project playback benchmark yet.

Video tracks are silent, matching the project model. Sound is placed separately
on audio tracks; automatic linked audiovisual placement remains later work.
Split, trim, move/lift, export, and persistent history are still pending.

The timeline currently caps its width at two million CSS pixels and its ruler
at 500 ticks. Very long sequences may require zooming out; virtualization and
large-project navigation are later work. Imported source timestamps are respected;
the viewer can be blank before the first picture or in gaps. The source-preview
path does not yet perform Tandem's later media-analysis corrections.
