## Implemented behavior

- 049: The shared painter applies fractional source crop before placement, keeping
  the uncropped source center and fit. Crop values clamp to 0-1; meeting or
  overlapping edges draw no area. Opacity clamps to 0-1 and multiplies source
  alpha during compositing. Video, image, and solid layers use the same path.
  Inspector controls patch position, scale, clockwise rotation, opacity, and four
  crop edges through `updateClip`. Linked selections have an explicit Picture clip
  selector so edits target the intended picture rather than its linked partner.
- 050: `applyLayout` implements Full, PiP right/left, Split, and Fill. PiP uses
  scale 0.5 at 0.87/0.77 or 0.13/0.77, enables the reference portrait cutout, and
  inserts the default shadow only if none exists. Full, Split, and Fill disable
  existing cutout and remove shadows while retaining other effects. Split routes
  camera right and other roles left, with quarter-source crops. Fill derives
  cover scale from source/canvas dimensions. Layouts clear transform keys while
  retaining other animation. Inspector actions apply presets and reset to Full.
  PiP settings are preserved faithfully, but cutout/shadow rendering is still
  pending and produces an explicit preflight issue.
- 051: `zoomToRegion` validates a normalized source rectangle and requires probed
  dimensions. The reference geometry fits the region inside the canvas, never
  scales below 1, and clamps placement to source edges. Static zoom updates only
  position/scale and clears their keys. Animated zoom accepts a timeline start,
  defaults to 0.5 seconds, resolves the current transform, and inserts easeInOut
  endpoints while preserving keys outside the interval. A held lead-in is added
  when needed. Invalid, nonpositive, or out-of-clip animation spans reject
  atomically. The inspector opens an original-source preview for pointer-drawn
  rectangles, with numeric coordinates as a keyboard alternative and optional
  animation from the playhead.
- 052: `setKeyframes` supports the reference fixed and effect-ID parameter paths,
  sorts keys, and clears a path with an empty list. It changes only that path and
  warns for unknown paths. Value decoding accepts numbers, points, RGBA colors,
  booleans, and strings. Evaluation uses clip-relative time and the starting
  key's linear, cubic easeIn/easeOut/easeInOut, or hold interpolation. Values hold
  before/after the endpoints; booleans, strings, and mismatched types hold until
  the next key. Color-wheel hue takes the short path around 360 degrees; ordinary
  rotation remains a number. The shared picture plan resolves transform, crop,
  and opacity before painting. Effect and audio properties can be resolved in
  core, but their rendering remains in later phases. Unknown paths are retained
  and ignored rather than changing the rendered picture.
- 053: One keyframe editor serves picture, gain, and existing effect parameters.
  It has an explicit clip selector, parameter/value/interpolation inputs,
  add/update/remove at the playhead, and previous/next navigation. New keys use
  clip-relative time; an existing key at the same flick time is replaced without
  changing other paths. A parameter selection survives edits. Effect parameters
  are discovered from stored effect IDs and parameter names. The UI explicitly
  identifies effect/sound rendering as pending. Read-only/locked clips cannot
  mutate keys, and adding outside the clip is disabled.
- 054: `addMotion` implements zoomIn, zoomOut, panLeft, panRight, panUp, and panDown.
  Amount defaults to 1.12 and accepts 1-3. Zoom endpoints use the existing base
  transform. Pans use existing source overflow, increasing scale by the amount
  when room is below 0.02, and travel through 80% of the available overflow.
  Position/scale keys span the full clip with linear interpolation; other keys
  remain. Controls expose style, amount, and the clip's duration. Trim the clip to
  change motion duration, matching the reference command's full-clip behavior.

Commands run through the existing atomic coordinator, revisions, undo/redo,
validation, deterministic ID generation, journal, and save queue. No dependency
or animation library was added. These animations belong to the edited video;
no decorative interface animation was introduced.

## Remaining limits

Only Windows Chromium was verified. Firefox/WebKit, macOS/Linux, native Tandem
reopening, accessibility auditing, and real touch hardware remain unverified.
Phase 028's public hosted-URL acceptance remains pending. No deployment was made.

PiP preserves cutout/shadow data; those renderers are still pending. Other effects,
transitions, titles, graphics, alternate formats, sound gain/effect rendering,
audio speed correction, speech levelling, and mixing remain later work. Effect
and audio keys are editable and resolve in core, but do not imply an implemented
sound/effect processor. Audible unsupported sound still fails preflight.

Motion uses the current transform, as the reference does. Apply Fill before a
photo move when the source must cover the canvas. Region zoom fits a rectangle
inside the canvas; a differently shaped region may leave space along one axis.
Animated zoom requires a positive duration inside the clip. Per-value codec and
color tolerances are synthetic checks, not native-reference pixel comparisons.

Prior journal retention/save-load cost, one-backup recovery, browser-storage
eviction, 20 MB project import, five-minute output, 1-60 fps, 1080p, codec, and
memory limits remain. Interactive undo history still resets on reload. These
checks do not establish complete Tandem or cross-platform parity.
